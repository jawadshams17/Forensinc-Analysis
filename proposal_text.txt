
RESEARCH PROPOSAL
Adversarial Robustness of Memory-Forensic Ensemble Classifiers Under Cloud Ephemerality
Extending SHAP-Guided Detection from Static Images to Time-Constrained VM Snapshots


1. Title and Abstract
Abstract (187 words)
Memory-forensic malware classifiers built on the CIC-MalMem-2022 benchmark — including the authors' own soft-voting RF+XGBoost+LightGBM+SHAP ensemble (99.99% accuracy, 0.017% FPR) — are trained and evaluated under an implicit assumption that the acquired memory image is complete and static. This assumption fails in ephemeral cloud infrastructure, where Spot Instances and preemptible VMs are terminated on notice windows as short as 30 seconds to 2 minutes, forcing incident responders to work from partial memory captures. An adversary aware that detection is memory-forensics-based can time obfuscation to exploit this truncation window. This proposal addresses the unexamined intersection of two active but separate research threads: adversarial-robustness-aware memory forensics (XMal; SHAP-Guided Feature Refinement) and ephemeral-cloud forensic timing gaps (Dhital and Kadobayashi, APIT 2026). The study is deliberately scoped: a mandatory feasibility gate validates that a small, concretely specified set of functionality-preserving memory-feature perturbations — adapted from Demetrio et al.'s black-box PE-evasion methodology — is both executable within realistic cloud interruption-notice windows and effective against the ensemble, before any large-scale acquisition campaign proceeds. We hypothesize measurable, quantifiable degradation in ensemble accuracy and SHAP feature-importance stability as capture completeness decreases, with implications for real-time cloud incident response.

2. Introduction and Problem Statement
Memory forensics has become a central pillar of fileless-malware detection because such malware, by design, leaves negligible disk artifacts and instead manipulates volatile memory structures — injected code, hollowed processes, and reflectively loaded libraries — that only a RAM capture can reveal [1]. Machine-learning classifiers trained on statistical memory-feature sets, most notably the CIC-MalMem-2022 benchmark introduced by Carrier et al. [2], have achieved near-perfect laboratory accuracy. The authors' own prior work demonstrated a soft-voting ensemble of Random Forest, XGBoost, and LightGBM with SHAP-based explainability and automated mitigation, achieving 99.99% accuracy and 0.017% false-positive rate on this benchmark, using the Volatility framework for feature extraction.
That result, like almost all published work on this benchmark, rests on a capture model inherited from on-premise forensics: the memory image is acquired from a host that is not actively being terminated, and the full 55-feature VolMemLyzer vector [3] is available at inference time. Cloud-native, ephemeral compute breaks this model in two compounding ways. First, ephemeral instances — AWS Spot Instances reclaimed with roughly a two-minute interruption notice, and GCP preemptible/Spot VMs reclaimed with a 30-second notice — impose a hard, adversary-exploitable ceiling on acquisition time. Recent work by Dhital and Kadobayashi has empirically characterized this as a forensic “blind spot”: short-lived VM activity can begin and conclude within the interruption-notice window, before a full memory image can be pulled and before continuous cloud-native monitoring services register the behavior [4]. Second, and left unaddressed by that timing-gap literature, an adversary who knows that detection is memory-forensics-based gains a new and cloud-specific evasion primitive: rather than only obfuscating features, the adversary can time the obfuscation, or the malicious activity itself, to coincide with the truncation window, so that whatever partial feature vector is captured is both incomplete and adversarially shaped.
Existing adversarial-robustness work on CIC-MalMem-2022 — XMal [5] and SHAP-Guided Feature Refinement (SHAP-GFR) [6] — evaluates robustness against feature-space perturbations (Gaussian noise, FGSM, PGD) but always against a complete memory image. Neither varies capture completeness. Conversely, the ephemeral-cloud forensics literature [4] measures the acquisition-timing gap but does not inject adversarial samples or measure classifier degradation. No published study has combined truncated/partial capture with adversarial evasion on this benchmark. This proposal fills that seam: it asks whether robustness claims established under complete-capture conditions survive when the capture itself is time-constrained and adversarially timed — a condition that is now the operational norm, not the exception, for a large and growing share of cloud workloads.
2.1 Scope Boundary
A prior draft of this proposal treated the full intersection of truncation, adversarial evasion, cross-architecture robustness comparison, and an external poisoned-dataset benchmark as a single, equally weighted campaign. That scope is not defensible within a 3–6 month window given that the central technical step — adapting a PE-file evasion methodology to a fundamentally different feature domain — has no existing precedent to build on and is therefore the project's primary risk, not a solved sub-problem. This revision separates the work into:
Core deliverable (committed): RQ1–RQ3, answered on the authors' own testbed captures, gated by a mandatory feasibility pilot (Section 5.3.1) before any full-scale campaign is funded or run.
Extended scope (contingent on Phase 0 success and remaining budget): RQ4 (time-to-first-reliable-detection under real cloud timing) and RQ5 (replication of the SHAP-GFR cross-architecture comparison), plus secondary validation against the external poisoned-dataset benchmark. These are reported as stretch outcomes, not promised results.
This restructuring directly narrows the claims the proposal is accountable for, and moves the highest-risk technical component (Section 5.3) to the front of the timeline rather than the middle.
3. Literature Review and Related Work
Memory-forensic ML detection on CIC-MalMem-2022. Carrier et al. introduced the CIC-MalMem-2022 (MalMemAnalysis-2022) dataset — 58,596 memory dumps evenly split between benign and malicious (Ransomware, Spyware, Trojan) samples, each represented by 55 VolMemLyzer-extracted features — and reported 99.00% accuracy/99.02% F1 with a Random Forest baseline [2]. Subsequent work has pushed accuracy toward ceiling: XGBoost variants report up to 99.98% accuracy [7], and the authors' own IEEE-published ensemble (RF+XGBoost+LightGBM soft voting with SHAP) reported 99.99% accuracy and 0.017% FPR. A parallel line of work targets generalization rather than raw accuracy: a lightweight, interpretable zero-shot approach evaluates detection of unseen obfuscated-malware variants rather than held-out samples from known families [8].
Explainability as a design constraint. Alani, Mashatan, and Miri's XMal reduces the 55-feature space to five features via recursive feature elimination guided by SHAP, achieving over 99.8% accuracy at 5.2 µs per-sample inference while explicitly targeting lightweight, explainable deployment [5]. This establishes SHAP not merely as a post-hoc explanation layer but as a feature-selection mechanism — a precedent this proposal extends into the truncated-capture setting, where feature availability, not just feature count, is time-constrained.
Adversarial-robustness-aware memory forensics. The SHAP-Guided Feature Refinement (SHAP-GFR) study refines the 55 CIC-MalMem-2022 features to 13 via mutual information and a novel SHAP-guided refinement process, benchmarks five classifiers (RF, XGBoost, MLP, 1D-CNN, CNN-LSTM), and stress-tests them under Gaussian noise, FGSM, and PGD [6]. It reports that tree ensembles degrade substantially under these feature-space attacks while 1D-CNNs retain roughly 97% of their F1 score. This is the closest prior work to the present proposal and the primary novelty boundary this proposal must clear: SHAP-GFR's robustness claims are established exclusively against complete, well-formed feature vectors — the attack perturbs feature values, never feature availability.
Explainability-guided evasion. Outside the memory-forensics subfield, Aryal et al. demonstrate that SHAP and similar explanation outputs can themselves be weaponized to guide adversarial evasion against malware detectors, using feature-importance rankings to prioritize which features to perturb for minimum-cost evasion [9]. This motivates our fourth evaluation axis (SHAP feature-importance drift under attack): if an adversary can read or infer which features the ensemble weights most heavily under partial capture, the truncation window itself becomes an attack-surface amplifier.
Functionality-preserving adversarial malware. In the PE-malware domain, Demetrio et al.'s GAMMA framework formalizes black-box, query-efficient, functionality-preserving evasion as a constrained optimization over benign-content injection, evading static detectors and multiple commercial antivirus engines with small payloads [10], building on the broader “Adversarial EXEmples” survey of practical attacks on Windows malware classifiers [11]. These methods operate on PE structure (headers, sections); no published work adapts this optimization framing to the memory-feature space (process counts, handle counts, injected-code indicators) that CIC-MalMem-2022-style classifiers consume. This is the second axis of extension this proposal undertakes.
Ephemeral cloud forensics. Alharthi and Garcia's 2026 study on forensic blind spots in ephemeral cloud VMs empirically measures the interruption-notice timing gap on AWS, showing that brief in-memory activity (e.g., metadata-credential theft, transient cryptomining) can complete before continuous detection services register it, and evaluates commercial detection services (Amazon Inspector, Detective) against this gap using LiME-based acquisition [4]. This work establishes the ephemerality problem empirically but is not adversarial: it does not inject evasion-optimized samples, and it does not measure ML-classifier degradation as a function of capture completeness.
Gap statement. Across these threads, three claims independently hold: (i) ensemble+SHAP classifiers on CIC-MalMem-2022 are near-perfectly accurate under complete capture; (ii) those same classifiers, and related architectures, degrade under feature-space adversarial perturbation of complete captures; (iii) ephemeral cloud VMs impose a real, measured acquisition-timing gap. No study has combined (ii) and (iii) — i.e., adversarial evasion applied under realistic, truncated, cloud-ephemeral capture conditions — leaving open whether published robustness numbers for memory-forensic classifiers hold, degrade gracefully, or collapse once the completeness assumption is removed.
4. Research Questions and Objectives
RQ1.  How does ensemble (RF+XGBoost+LightGBM) detection accuracy and F1 score degrade as a function of memory-capture truncation percentage, absent any adversarial manipulation?
RQ2.  Does the evasion success rate of functionality-preserving, memory-feature-space adversarial perturbations increase disproportionately (relative to the RQ1 baseline) when perturbations are applied to truncated captures rather than complete ones?
RQ3.  How much does SHAP global and local feature-importance ranking drift between clean, truncated, and adversarial-truncated capture conditions, and does this drift correlate with degraded detection reliability?
RQ4 (extended scope).  What is the minimum capture window (time-to-first-reliable-detection) required for the ensemble to sustain a pre-specified accuracy/F1 floor (e.g., ≥95%) under adversarial conditions, and how does this compare to typical Spot/preemptible interruption-notice windows?
RQ5 (extended scope).  Do robustness rankings among classifiers (tree ensembles vs. the SHAP-GFR benchmark architectures) established under complete-capture adversarial testing [6] hold, reorder, or invert under truncated-capture adversarial testing?
5. Proposed Methodology
5.1 Testbed
We instrument AWS Spot Instances and GCP preemptible/Spot VMs as an ephemeral acquisition testbed. Both providers deliver a bounded interruption notice (≈ 2 minutes on AWS, ≈ 30 seconds on GCP) before reclamation, which we treat as the ground-truth truncation clock rather than simulating it offline — this preserves the realism the ephemeral-forensics literature identifies as the operative constraint [4].
Assumption to confirm: budget and cloud-account access for sustained Spot/preemptible experimentation; if constrained, Section 9 describes a local-hypervisor fallback that trades ecological validity for cost control.
5.2 Malware injection and acquisition
Fileless malware samples (process-injection, reflective DLL loading, and living-off-the-land techniques consistent with the Ransomware/Spyware/Trojan categories in CIC-MalMem-2022 [2]) are executed on instrumented instances. Memory is acquired via LiME [12] at a series of controlled intervals prior to forced termination — e.g., 100%, 75%, 50%, 25%, and 10% of the available interruption-notice window — to construct a truncation-percentage axis. Each truncated capture is processed through the same VolMemLyzer-based feature-extraction pipeline used in the authors' Paper 1, ensuring the 55-feature representation is directly comparable across capture conditions; features that cannot be computed from a partial capture (e.g., process-handle enumerations requiring full traversal) are encoded as missing rather than imputed, so that the ensemble's native missing-value handling is exercised rather than masked.

5.3 Adversarial perturbation
This is the proposal's central technical risk, and is treated as such: it is specified formally, mapped to concrete VolMemLyzer feature categories, and gated by a mandatory feasibility pilot before any full-scale campaign is committed.
Perturbation space, mapped to features (not asserted in the abstract)
Demetrio et al.'s GAMMA framework treats evasion as a constrained minimization of classifier confidence subject to a payload-size (cost) penalty, over a space of functionality-preserving content-injection actions on a static PE file [10]. The memory-feature domain has no equivalent notion of “unused file space” — every VolMemLyzer feature is a live runtime statistic, not a static structural property, so the action space must be runtime actions with a measurable, single-feature (or narrowly-scoped) effect. The first three primitives are additive, do not touch the malware's own code path, and are the ones used for the core deliverable. The fourth (malfind dilution) is flagged high-risk and reserved for the extended-scope condition only, contingent on Phase 0 validation.
Formal objective
Let x ∈ ℝ⁵⁵ be the clean feature vector, δ ∈ Aᵏ a sequence of up to k primitive applications drawn from the action set A above, and fⁱ(x) the ensemble's soft-voting malicious-class probability. The optimizer selects:
δ* = argminδ∈Aᵏ  fθ(x ⊕ δ) + λ·c(δ)
subject to a query budget Q and a wall-clock budget Tadv, where ⊕ denotes applying the primitives' measured feature deltas to x, c(δ) penalizes the number of primitives applied (analogous to GAMMA's payload-size penalty), and λ trades off evasion strength against perturbation footprint. Optimization uses the same genetic/greedy black-box search strategy as GAMMA [10], since it is query-efficient by design and does not require gradient access to fθ, consistent with a realistic attacker who can only observe detection outcomes, not model internals.

5.3.1 Reconciling attacker query budget with the truncation window
A black-box optimizer that requires many queries against the live detector is not obviously compatible with an attacker who also has only seconds to tens-of-seconds of runtime before forced termination. This tension must be resolved explicitly rather than left implicit:
We do not assume the attacker optimizes online, in real time, against the live ensemble during the truncation window. That threat model would indeed be incoherent given GCP's ~30-second notice. Instead, consistent with the black-box threat model's own assumptions in [10, 11], we assume the attacker has pre-computed an effective perturbation sequence δ* offline, against a surrogate copy of the detection pipeline (trainable from public knowledge that the target uses a memory-forensic ML ensemble on standard VolMemLyzer features, per the problem statement's premise), and deploys δ* at runtime as a fixed, low-cost action sequence requiring no further queries during the live window.
Under this — realistic and literature-consistent — separation of offline crafting from online deployment, the only budget that must fit inside the truncation window is the execution cost of applying the pre-computed primitives (process spawns, DLL loads, handle opens), which is on the order of milliseconds to low seconds, not the optimizer's query budget Q.
The offline crafting cost (Q, T_adv) is instead bounded and reported separately, against a stationary local copy of the ensemble, and is not claimed to occur within the cloud interruption window at all.
This reframing is itself a testable design choice, not a given: Phase 0 (below) includes an explicit test of whether pre-computed, non-adaptive perturbations retain evasion effectiveness against the live ensemble, since a defender could in principle detect the pattern of a fixed perturbation sequence even if it evades the feature-level classifier. This is registered as a named limitation in Section 9, not resolved by assumption.

5.4 Benchmarks
The core deliverable uses only the constructed truncated/adversarial CIC-MalMem-2022-derived captures from 5.2–5.3, on the authors' own testbed — this keeps the primary result independent of any external asset the authors cannot yet verify. As an extended-scope, non-critical secondary validation, we will additionally evaluate against A Multi-Attack Labeled Poisoned Dataset Suite for CIC-MalMem-2022 and CCCS-CIC-AndMal-2020 (Ahsan Ul Islam, IEEE DataPort, 2026, DOI: 10.21227/xskt-bj85), which provides eight row-labeled data-integrity attack variants (label flipping, backdoor injection, feature poisoning, Gaussian-noise injection, outlier injection, missing-value injection, sample duplication, class-imbalance removal) built on CIC-MalMem-2022. This dataset is verified and citable; however, its poisoning attacks operate on training-data integrity, not on inference-time evasion or capture truncation, so it validates a related but distinct threat model and is used only as a complementary robustness cross-check, not as a substitute for the core adversarial-evasion result.
5.5 Pipeline and algorithms
The classification pipeline reuses the Paper 1 architecture unchanged in its learning algorithms — soft-voting ensemble of Random Forest, XGBoost, and LightGBM — to isolate capture-completeness and adversarial effects from confounding architectural changes. SHAP (TreeExplainer) is computed at each truncation/adversarial condition for both global feature-importance ranking and per-sample local explanations, following the same explainability role established in XMal [5] and SHAP-GFR [6].
5.6 Evaluation metrics
Accuracy/F1 degradation curve vs. capture-window truncation percentage (RQ1).
Evasion success rate of adversarial samples, measured separately pre- and post-truncation, at matched query budgets (RQ2).
SHAP global feature-importance rank correlation (Spearman's ρ) between clean-complete, truncated-clean, and truncated-adversarial conditions (RQ3).
(Extended scope) Time-to-first-reliable-detection: the minimum elapsed capture time at which running accuracy crosses the pre-specified floor, reported against measured AWS/GCP interruption-notice windows (RQ4).
(Extended scope) Per-classifier robustness ranking stability, compared against the SHAP-GFR results as reported in the literature [6] under the truncated condition (RQ5). This is framed as a comparison against published numbers, not a byte-for-byte protocol replication, since the SHAP-GFR authorship and exact experimental configuration remain unconfirmed at proposal-drafting time (see Section 9); if full replication becomes possible once the citation is resolved, RQ5 is upgraded accordingly.

5.7 Improvement over related work
The core deliverable improves on [5] and [6] by making capture completeness a first-class independent variable rather than an implicit constant, and improves on [4] by adding the adversarial dimension explicitly identified as future work in that study — while, per Section 5.3.1, being explicit about which part of the adversarial pipeline (offline crafting vs. online deployment) is claimed to fit inside the truncation window. It also converts SHAP from a purely explanatory artifact into a diagnostic instrument for robustness, tracking importance drift as a leading indicator of unreliable detection rather than only explaining individual predictions post hoc.
6. Novelty and Contribution Statement
First combined threat model. This is, to the authors' knowledge, the first study to jointly manipulate memory-capture completeness and adversarial evasion on CIC-MalMem-2022-style memory-feature classifiers, closing the gap between adversarial-robustness work [5, 6] and ephemeral-cloud timing-gap work [4].
Cloud-realistic adversarial methodology. By adapting functionality-preserving black-box optimization [10, 11] from PE-header space to runtime memory-feature space, and by acquiring on genuinely ephemeral Spot/preemptible infrastructure rather than simulating truncation offline, the study produces evasion and degradation estimates with higher ecological validity than laboratory-only perturbation studies.
SHAP as a robustness diagnostic. The proposal repurposes SHAP feature-importance drift — previously used mainly for post hoc explanation [5] or as an attack-guidance signal [9] — as a quantitative, pre-registered robustness metric (RQ3), offering practitioners an operational early-warning signal distinct from raw accuracy.
7. Expected Results and Evaluation Plan
We hypothesize, but do not assert as established fact, that: (H1) accuracy and F1 will degrade monotonically as truncation percentage increases, with the tree-ensemble architecture showing steeper degradation than the CNN-based architectures benchmarked in SHAP-GFR [6], consistent with that study's clean-capture adversarial findings; (H2) evasion success rate under adversarial perturbation will be measurably higher on truncated captures than on complete captures at matched query budgets, because fewer available features reduce the ensemble's redundancy margin; (H3) SHAP feature-importance rankings will show statistically significant rank instability (ρ meaningfully below 1) between clean-complete and truncated-adversarial conditions.
Baselines
(a) The authors' unmodified Paper 1 ensemble evaluated only on complete, non-adversarial captures (upper-bound reference); (b) a random-guessing and a majority-class classifier as sanity floors; (c) (extended scope) published SHAP-GFR figures [6] as a literature comparison point for RQ5, not a re-run protocol, given the unresolved citation status noted in Section 9.
Success criteria
The core deliverable is considered to have produced a positive result if it either (i) demonstrates statistically significant degradation curves answering RQ1–RQ3 with 95% confidence intervals computed via bootstrap resampling across acquisition trials, or (ii) demonstrates that degradation is not significant — a negative result that would itself be publishable, since it would show the existing ensemble is more cloud-ready than assumed. RQ4–RQ5 are reported only if the extended-scope work is reached.
Ablation plan
Core: (i) truncation percentage alone (no adversary), (ii) adversarial perturbation alone (complete capture — an internal sanity check, not a replication of [6]), (iii) the combined condition. Extended scope, contingent on Phase 0 success and remaining budget: (iv) feature-subset ablation comparing the full 55-feature set against a mutual-information-reduced subset, to test whether feature reduction helps or hurts truncation robustness independent of the SHAP-GFR-specific 13-feature set.
8. Timeline

If Phase 0 fails its go/no-go criteria, Phase 2 is re-scoped to truncation-only data collection (RQ1) and Phases 3–5 proceed on that narrower basis, preserving a publishable outcome without the adversarial claim.
9. Limitations and Risks
Adversarial-mechanism transfer risk (primary risk). The core, unresolved scientific risk is that functionality-preserving evasion — well-established for static PE structure [10, 11] — may not transfer cleanly to live runtime memory statistics, where every feature reflects an actual running process state rather than unused file space. Mitigation: this is not treated as a background risk to disclose after the fact; it is the explicit subject of the Phase 0 go/no-go gate (Section 5.3.2), which can terminate the adversarial arm of the study before cloud resources are committed, leaving a smaller but still-publishable truncation-only result.
Cloud cost and access constraints. Feasibility estimate: at current AWS Spot pricing for small general-purpose instances (roughly USD 0.01–0.03/instance-hour), a core campaign of ~500 short-lived acquisition trials (5 truncation levels × 2 conditions × 3–5 families × ~2 provider types × repetitions) is estimated at well under USD 500 in compute, with the binding constraint being engineering time for orchestration and dynamic-analysis validation, not raw spend. Mitigation: batch experiments during off-peak Spot pricing windows; fall back to a local KVM/QEMU hypervisor with artificially injected interruption signals if cloud account access is restricted, explicitly flagged as a lower-ecological-validity substitute.
Functionality-preservation validation is manual-labor-intensive. Confirming that each memory-feature manipulation preserves malicious functionality across fileless-malware families requires per-sample dynamic verification. Mitigation: restrict the adversarial sample set to a tractable, pre-registered subset of malware families (e.g., 3–5 representative families per category) rather than the full CIC-MalMem-2022 taxonomy, and front-load this validation into Phase 0 rather than discovering infeasibility mid-campaign.
Non-determinism of cloud reclamation timing. Actual interruption notice delivery can vary slightly around nominal windows, complicating precise truncation-percentage control. Mitigation: log actual notice-to-termination intervals per trial and report truncation as measured, not nominal, time.
Offline-crafting/online-deployment separation is a modeling assumption, not a proven equivalence. Section 5.3.1 assumes an attacker can pre-compute an evasive perturbation offline and deploy it as a fixed action sequence within the truncation window, rather than optimizing online. This resolves the query-budget-vs-truncation-window tension analytically, but the assumption that a non-adaptive pre-computed perturbation retains its evasion effectiveness against the live ensemble is itself tested only in Phase 0, criterion 3, on a limited sample; a fuller robustness argument for this assumption is deferred to extended scope.
SHAP-GFR citation remains unresolved. Despite a second verification pass, the authors could not independently confirm the authorship or venue of the SHAP-Guided Feature Refinement study [6] beyond a consistently recurring abstract indexed across secondary sources (ResearchGate citation panels). Mitigation: [6] is no longer used as a core benchmark or replication target (see Sections 5.4, 5.6, 7); it is retained only as a literature comparison point under extended scope, and the citation will be corrected or the comparison dropped entirely once the source is located, prior to submission.
Poisoned-benchmark citation — resolved. The IEEE DataPort poisoned CIC-MalMem-2022 suite has now been independently verified: Ahsan Ul Islam, “A Multi-Attack Labeled Poisoned Dataset Suite for CIC-MalMem-2022 and CCCS-CIC-AndMal-2020,” IEEE DataPort, 2026, DOI 10.21227/xskt-bj85. It remains extended-scope (Section 5.4) because it validates training-data poisoning, not inference-time truncation/evasion — a different threat model from this proposal's core claim.
Novelty erosion risk. Given the pace of publication in this subfield (multiple closely related works identified within 2023–2026), a competing group could publish the same intersection before this timeline completes. Mitigation: early preprint release of Phase 0–1 methodology and results to establish priority, independent of full-campaign completion.
